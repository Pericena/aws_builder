## MAPA DEL BOOTCAMP

- **Semana 0 — Inicio y exploración de AWS:** se presenta el punto de partida del proceso de aprendizaje.
- **Semana 1 — AWS EC2 + Docker + Odoo + experiencia práctica desde el celular:** la publicación de planificación se conserva como antecedente; la publicación posterior se identifica como entrega final y enlaza el repositorio del e-commerce.
- **Semana 2 — Primer acercamiento a Cloud Security:** una tarea revisa seguridad básica de un servidor; la otra propone una charla práctica sobre el mismo tema. Son publicaciones distintas y ambas se conservan.
- **Semana 3 — Construcción del proyecto AWS Cloud Security Lab:** comienza la documentación del laboratorio práctico y se enlaza su repositorio.
- **Semana 4 — Reflexión, documentación y estrategia para continuar creando contenido:** se resume el camino de aprendizaje y se presenta un plan futuro de temas.

## CONTENIDO FINAL DEL BOOTCAMP

### Recomendación: AWS Cloud Security Lab

**Repositorio propuesto como contenido final:**

https://github.com/Pericena/aws_builder/tree/main/cloud_security_lab

Es el candidato más sólido entre los elementos compartidos porque:

- Está relacionado directamente con AWS y Cloud Security.
- Se presenta como un proyecto práctico propio, no solo como una reflexión.
- Reúne temas técnicos mencionados durante el Bootcamp: EC2, Security Groups, IAM, MFA, CloudWatch y CloudTrail.
- Está vinculado a la publicación de la Semana 3 y vuelve a aparecer en la Semana 4.
- La URL de GitHub permite presentar el proyecto como evidencia pública del proceso de aprendizaje.

Las publicaciones de las semanas 0, 1 y 2 sirven como evidencia del recorrido y del aprendizaje; la publicación de Semana 4 documenta la reflexión y el plan de continuidad. No sustituyen al proyecto técnico como pieza final. El repositorio de e-commerce de la Semana 1 es un proyecto relacionado con AWS, pero el AWS Cloud Security Lab representa mejor la evolución descrita hacia Cloud Security.

**Comprobación antes de presentarlo:** el README del laboratorio plantea una construcción progresiva y enumera fases de trabajo. Antes de declarar el proyecto como terminado, confirma que el repositorio contiene evidencia de lo que realmente realizaste (por ejemplo, documentación, configuraciones o resultados). No afirmes que desplegaste o completaste componentes que no estén respaldados por tu trabajo publicado.
